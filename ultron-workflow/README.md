## 🆕 What's New

### v1.0 — Single-Server Web UI (current)
- **One port, one command.** `python web.py` now serves both the Flask API and the Vite SPA at `http://localhost:5000`. No Electron, no native build, no MSI.
- **SPA served from Flask.** `vite build → ultron-workflow/dist/` is served by `web.py` with SPA fallback and immutable caching for hashed `assets/*`.
- **Code-split heavy labs.** `three` / `@react-three/fiber` / `pyodide` are lazy-loaded — initial load stays < 600 kB.
- **CSRF hardening.** Cross-origin `POST` without matching `Origin`/`Referer` is rejected with `403` (protects `/api/terminate` and other state-changing endpoints).
- **Caching overhaul.** Flask-Caching (`simple` or `Redis`) + `core.cache.CacheManager` with versioned keys, `X-Cache: HIT/MISS` headers, and auto-invalidation when skills/recipes/config change.

## 🏗 Architecture — Single Server at `localhost:5000`

No separate desktop binary or native runtime. The entire UI is a Vite + React SPA built to `ultron-workflow/dist/` and **served by the Flask backend** (`web.py`).

```
Browser  →  http://localhost:5000              SPA (Vite dist, SPA fallback, no-cache HTML)
         →  http://localhost:5000/app          legacy alias → /
         →  http://localhost:5000/assets/*     hashed Vite assets → immutable (1y)
         →  http://localhost:5000/api/*        Flask JSON APIs
```

```
┌──────────────────────────────────────────────────────────────┐
│  web.py  (Flask, :5000)                                     │
│  ├─ / , /app , /assets/*  → serves ultron-workflow/dist/   │
│  ├─ /api/protein-lab/run  → skills/protein_lab.py           │
│  ├─ /api/dna-lab/run|batch|fetch → skills/dna_lab.py       │
│  ├─ /api/boltz/run        → skills/boltz_2.py (Boltz-2)    │
│  ├─ /api/chat + /api/state → core/engine.py (agent)        │
│  ├─ /api/skills|recipes|models|voice|metrics …              │
│  └─ /api/update/check|apply → core/updater.py (beta)       │
└──────────────────────────────────────────────────────────────┘
         ▲
         │  localStorage autosave
┌────────┴────────┐
│  Vite + React 19 SPA (ultron-workflow/)                      │
│  src/components/App.tsx → DesktopTabs (Alt+1..7)             │
│  src/components/workflow/ → Canvas, NodePalette, Properties, │
│                               ExecutionLog, MiniMap          │
│  src/store/workflowStore.ts (Zustand)                        │
│  src/core/executionEngine.ts (topological + branching)       │
│  src/nodes/* (19 types, auto-registered)                     │
│  src/browser-api.ts (file picker + Blob downloads)           │
│  src/utils/workflowIO.ts (versioned JSON envelope)           │
└─────────────────────────────────────────────────────────────┘
```

**Why this is better than a native shell:**
- One command to run everything — `python web.py` serves both API and UI.
- No native build chain, signing keys, or MSI installers.
- Works on any OS with Python + Node.
- Vite code-splits heavy labs (`three`, `pyodide`, `mech`) — initial load stays lean.

### How it works (nuts and bolts)

- `vite.config.ts` builds to `dist/` with `base: '/'` — Flask serves that dist with SPA fallback.
- `web.py:DIST = ultron-workflow/dist` + routes `/`, `/app/<path>`, `/assets/<path>` handle HTML vs hashed assets vs fallback.
- `src/browser-api.ts` provides browser-only file I/O (`<input type="file">` + Blob downloads) — no native FS.
- `src/store/appIntegration.ts` + `src/utils/workflowIO.ts` handle autosave/restore via `localStorage` + downloads/exports.
- `core/cache.py` + `flask_caching` (Redis or `simple`) cache shell the hottest `GET`s; `X-Cache: HIT/MISS` header confirms it.

## ⬇️ Download & Installation

### Option A — Git clone (recommended, required for auto-update)

```bash
# 1. Clone (pick one)
git clone https://github.com/Ichor44/Ultron_Workflow.git
# — or if your remote is the parent A.G.E.N.T repo —
git clone https://github.com/Ichor44/A.G.E.N.T.git

# 2. Enter
cd Ultron_Workflow          # or cd A.G.E.N.T

# 3. Python env (pick one)
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt

# 4. Frontend
cd ultron-workflow
npm install
npm run build               # → dist/ (served by web.py at /)
cd ..

# 5. Configure
copy .env.example .env      # Windows
# cp .env.example .env      # macOS/Linux
# Edit .env with your keys (see Configuration below)
```

The repo is usable without keys — it starts in **mock mode** (chat and labs fall back to local parsing).

### Option B — ZIP download (no git)

1. On GitHub, **Code → Download ZIP**.
2. Extract, then follow steps 3–5 from Option A.
3. Auto-update (beta) will report `Self-update not configured` — that's expected without a git clone. You can still update by re-downloading the ZIP.

### Option C — Docker (all-in-one)

```bash
# From repo root (where docker-compose.yml + Dockerfile live)
copy .env.example .env   # set keys first
docker compose up --build
# → http://localhost:5000
# Redis is included as ultron-redis (optional but auto-detected via REDIS_URL)
```

Data survives restarts via volumes: `data/`, `skills/`, `recipes/`, `proposals/`, `output/`, `logs/`.

## 🔄 Auto-Update (Beta)

> **Status: beta.** Works today when deployed from a **git clone** with `ULTRON_REPO_URL` set. Includes branch tracking, hard-reset + clean, conditional `pip install`, and optional auto-restart. Authentication for private remotes uses the credential helper configured on the host (no interactive prompts — it fails fast).

### How it works

```
GET  /api/update/check   compare  HEAD  vs  origin/<BRANCH>
POST /api/update/apply   git fetch → git reset --hard origin/<BRANCH>
                         → git clean -fd (keeps data/ logs/ output/ .env)
                         → pip install -r requirements.txt if changed
                         → optionally os._exit(0) so Docker/supervisor restarts
```

- `core/updater.py` is the engine; `data/`, `logs/`, `output/`, `.env` are **never touched** (untracked files).
- `VERSION` at the repo root is the human version; commits are the precise version.
- Concurrency lock prevents two applies at once. Neutralizes credential prompts (`credential.interactive=false`, `core.askPass=`).
- Handles `safe.directory=*` for container UID mismatches.

### Setup

```bash
# 1. Must be a git clone (not a ZIP)
git status   # should succeed

# 2. Configure env (in .env or shell)
ULTRON_REPO_URL=https://github.com/Ichor44/Ultron_Workflow.git
ULTRON_UPDATE_BRANCH=main
# Inside Docker ULTRON_AUTO_RESTART defaults to 1; outside it defaults to 0.
# Set explicitly if you want control locally:
ULTRON_AUTO_RESTART=0   # manual restart after update (safer outside Docker)

# 3. Restart web.py so it picks up the env, then use the API:
curl http://localhost:5000/api/update/check | jq
curl -X POST http://localhost:5000/api/update/apply | jq
```

The UI calls these at `GET /api/update/check` and `POST /api/update/apply`; when `configured: false` it shows:

> `Self-update not configured. Set ULTRON_REPO_URL and deploy from a git clone.`

### Limitations (beta)

- ZIP installs cannot self-update (no `.git`). Re-download the ZIP.
- Private repos need a pre-configured credential helper or deploy key; interactive auth is blocked by design.
- Non-git runtime edits (untracked files) are preserved but local tracked-file edits are discarded by `reset --hard` — commit on a branch first.

## 🧩 Workflow Builder Guide

1. **Add nodes** from the palette (grouped by category) onto the canvas.
2. **Connect** outputs → inputs by dragging ports (typed: `string | number | boolean | object | array | any | llm_messages | file_path | python_code`).
3. **Configure** each node in `PropertiesPanel` (supports `{{variable}}` interpolation).
4. **Run** with `F5` or toolbar ▶. Watch `ExecutionLog` (per-node status, latency, trace). Conditional branches are evaluated strictly.
5. **Persist**: `Ctrl+S` export (versioned JSON envelope via `workflowIO.ts`), `Ctrl+O` import (with validation), autosave to `localStorage` via `appIntegration.ts`.
6. **Templates** — `TemplateSelector` / `WorkflowTemplates.tsx` for starters.
7. **Undo/Redo**, minimap (`M`), grid, and command palette (`Ctrl+K`).

## 🔧 Troubleshooting

| Symptom | Fix |
|---------|-----|
| `dist not built` / blank page at `/` | `cd ultron-workflow && npm run build` then restart `web.py`. Launchers do this automatically. |
| `Agent is busy` (`429` from `/api/chat`) | Wait for the `thinking` turn to finish; poll `GET /api/state` until `done`/`error`/`awaiting`. |
| `SELF-UPDATE not configured` | Need a **git clone** + `ULTRON_REPO_URL` in env. ZIP installs show this by design. |
| Boltz-2 / Evo2 errors | Check `GET /api/biolab/health` and `GET /api/dna-lab/health`; set `NVIDIA_API_KEY`/`BOLTZ2_*`/`EVO2_*` in `.env`. |
| `403 cross-site request rejected` | You're `POST`ing from a different `Origin`; use the UI at `http://localhost:5000` or `curl` from `localhost`, or hit the same host. |
| `npm run build` tsc errors | `npm install` first; check `tsconfig.json` `skipLibCheck` is respected via `npm run build` (runs `tsc --noEmit --skipLibCheck`). |
| Port `5000` in use | `AGENT_PORT=5001 python web.py` (and point Vite `proxy` if using `npm run dev`). |
| Redis not used | Omit `REDIS_URL` → falls back to `simple` (in-memory). With `REDIS_URL`, `core/updater.py` pings Redis with 1s timeout to decide. |
